# P2 治理总控与台账协议 (Governance Ledger Protocol)

本协议定义复杂调研报告全生命周期的执行进度、授权边界、决策日志与四分状态治理规范。本文件为机器与协作参与者强制遵守之可执行准则。

---

## 1. 宪法原则引用与事实源规则

1. **唯一事实源约束**：`brief.md` 为全项目唯一事实源与权威锚点，后续课题分解、调研、大纲、合稿与治理动作均由其派生。口径与基准冲突时，必须 [SHALL] 以 `brief.md` 为准。
2. **项目宪法五底线原则引用规范**：项目宪法五项不可侵犯原则（事实判锤唯二通路、定性裁决权归人类、无隐藏状态、非同族对抗复核且审者只读、严禁跨口径相减）之权威文本内嵌于 `brief.md`「3. 项目宪法」小节。本协议必须 [SHALL] 仅引用其法理约束，严禁 [SHALL NOT] 在本文件或其他派生文件中复制或篡改宪法全文条目。
3. **治理台账从属性**：`progress-log.md` 作为过程控制中枢，其初始边界与任务目标必须 [SHALL] 严格对应 `brief.md` 的范围约定与交付目的地设定。
4. **权威载体不预设规则**：本技能不预设权威载体；权威由 `brief.md` §2.7 决定（严格限定为 `ONLINE_AUTHORITATIVE` 或 `LOCAL_AUTHORITATIVE`），且该字段为空或待定时 G0 门禁不可签。
5. **规划文件职责明晰**：规划文件由 `research-breakdown.md` ＋ `task.json`（M3 产物，调研规划）＋ `outline.md`（M5 产物，章节规划）承担；治理台账只记录其状态、哈希与门禁引用，不复制其具体内容。

---

## 2. 状态四分公理与误用禁令

系统确立四分状态公理，彻底消灭“文件已落地即代表完成”的隐式进展假象。

### 2.1 四分状态枚举定义
台账中的「四分状态」列取值必须 [SHALL] 严格限定于以下四项枚举，禁止 [SHALL NOT] 引入任何其他中间态或自定义值：
1. **存在**：
   - 语义：对应工件物理文件已在受控文件系统生成或初始化，具备基础文件结构与元数据。
   - 判定标准：文件物理路径存在且文件大小 > 0 字节。
   - 限制：仅表明工件初稿生成，严禁 [SHALL NOT] 假定其内容具备真实性、准确性或可用性。
2. **已复核**：
   - 语义：工件已经过独立审查者（非同族模型或零记忆隔离实例）的对抗性复核，或通过确定性代码级复算与规则扫描。
   - 判定标准：具备有效且可验证的复核证据（如 `review-reports/<boundary>_review.md` 及对应 provenance 记录），且 D0（已证实错误）缺陷数必须 [SHALL] 严格为 0。
   - 限制：已复核不代表已被人类采纳或定稿，禁止 [SHALL NOT] 擅自向下游不可逆阶段传递。
3. **已同步**：
   - 语义：工件或交付物已通过适配器受控镜像至目标在线文档或外设协同端。
   - 判定标准：远程载体版本 revision 与本地 Git 母本 commit/hash 记录一致，且同步记录已写入元数据。
   - 限制：仅代表物理传输闭环，禁止 [SHALL NOT] 视为人类决策通过。
4. **已审定**：
   - 语义：工件已获人类决策者在对应签署件（`gates/G0-approval.md` 至 `gates/G3-approval.md` 或 `gates/change-<id>-approval.md`）中签名批准。
   - 判定标准：签署件存在、字段齐全、决策为 `APPROVED`、签署人非 agent、`artifact_sha256` 逐字节匹配，且签署件**不含** `stub: true` 桩标记。
   - **两种记录方式**：`human_signed`（人类直接签署）与 `session_transcribed`（人类会话授权后由 Agent 代录）。代录模式下签署件必须包含 `authorization_quote`、`authorization_turn`、`authorization_at`、`authorized_by`、`recorded_by` 五个溯源字段，且 `authorized_by` 与 `signed_by` 一致、均为人类身份；缺一即不得判定为已审定。
   - 限制：具备最高法理效力，非经 M8 变更回路禁止 [SHALL NOT] 覆写。
   - **桩件硬拒绝**：门禁只接受真实人类签署件。凡声明 `stub: true`（或 `stub:true`）的演练桩、样板件、自动生成件，一律判定 `STUB_REJECTED`、`blocked=true`、退出码 1，即使哈希吻合也不得放行。G0/G1/G2/G3/change-<id> 五门共用此校验；测试中用于验证放行路径的夹具必须为无 stub 标记的人类格式文件，且测试 README 须声明「该夹具不代表真实人类签署」。

### 2.2 状态误用与越权禁令
1. **禁止材料存在即推断已审定**：禁止 [SHALL NOT] 仅因某阶段工件文件（如 `outline.md`、`datatable.csv`）在磁盘存在，即推断该任务已进入后续阶段。
2. **禁止跳过复核直接审定**：仅当 [ONLY WHEN] 边界复核状态为「已复核」且 D0 缺陷数为 0 时，方可 [THEN] 向人类提交门禁审批申请；禁止 [SHALL NOT] 在复核未通过前申请门禁审批。
3. **禁止以同步代替审定**：工件已同步至在线载体绝不等于获得通过，禁止 [SHALL NOT] 视线上存在为人类默认批准。

## 3. 台账维护规则与复选框防篡改

### 3.1 勾选权人类排他公理
1. **Agent 勾选剥夺**：治理台账中任务完成状态列 `- [ ]` 的勾选权严格归人类所有。任何 AI 智能体、脚本或自动化会话严禁 [SHALL NOT] 直接在台账中将 `- [ ]` 修改为 `- [x]`。
2. **Agent 建议列限定**：Agent 仅可 [ONLY WHEN] 在完成阶段性工作后，向独立的 `agent_建议` 列填写建议（如 `建议放行`、`待复核`、`待人审`、`待事件触发`），不得越权操作复选框。
3. **代打勾唯一授权通路**：仅当 [ONLY WHEN] 人类已在 `gates/*.md` 中签署 `APPROVED` 且哈希校验完全一致时，Agent 方可 [THEN] 依据该有效签署件更新复选框为 `- [x]`，且必须 [SHALL] 同步在「依据签署件与哈希」列明文记录签署件文件名与 `artifact_sha256`。代录模式（`session_transcribed`）的签署件同样适用，但须额外在台账中登记其 `authorization_turn`，使打勾依据可回溯到人类具体授权。

### 3.2 违规探测与强制回滚
1. **自评打勾强制拦截**：门禁与存储守护工具（`gate_guard.py` / `storage_guard.py`）在执行门禁判定或存储自检时，必须 [SHALL] 扫描台账全部任务行。
2. **越权篡改处理流程**：凡检测到任一任务行标记为 `[x]` 但对应 `gates/*.md` 签署件缺失、未批准、署名为 agent、或哈希不匹配者：
   - 守护程序必须 [SHALL] 立即将该行复选框强行回滚为 `[ ]`；
   - 守护程序必须 [SHALL] 向工作区根目录写入 `violations.log`，记录篡改时间、会话标识、违规任务 ID 及违规事实；
   - 守护程序必须 [SHALL] 输出阻断诊断 JSON，并以非零退出码（退出码 1）强制中断流程。

## 4. 授权边界 (Authorization Boundaries) 声明规范

台账第一节必须 [SHALL] 显式维护当前会话的权限边界，防止大模型发生角色泛化或越权动作。

### 4.1 授权边界格式约束
1. **active_session_id**：必须 [SHALL] 记录当前运行的真实会话 ID。
2. **authorized_operations**：必须 [SHALL] 显式列出本轮交互中人类明确授权或触发的具体操作。未在列表中列出的操作，默认均为未授权。
3. **prohibited_operations**：必须 [SHALL] 显式列出高危禁止动作列表，至少包括：
   - `"未经 G0 签署擅自启动后续调研规划"`
   - `"未经 G1 签字启动正文合稿"`
   - `"未经 G2 裁决静默覆盖线上或本地母本"`
   - `"未经 G3 终审对外正式提交文件"`
   - `"Agent 擅自修改任务完成复选框 [x]"`

### 4.2 动态流转要求
当人类在门禁中签署批准或下达新指令时，调度器必须 [SHALL] 同步刷新 `authorized_operations`，并将已完成的阶段性授权封存。

## 5. 决策日志 (Decision Log) 记录标准

台账第四节必须 [SHALL] 记录项目生命周期中涉及口径、结构、存废及取舍的全部关键人类裁决。

### 5.1 字段规范
每条决策记录必须 [SHALL] 包含以下 7 个字段，缺一不可：
- **决策 ID**：格式为 `D-###`（如 `D-001`）。
- **时间戳**：ISO 8601 标准时间（UTC 或本地带时区）。
- **触发事件/争议点**：记录引发决策的外部输入、异族复核分歧（D1/D2/D3）或数据冲突。
- **权衡选项 (Tradeoffs)**：明确记录至少两个备选方案及其利弊对比。
- **最终裁决结论**：记录人类拍板的定性决议。
- **裁决人**：明确记录人类身份标识，禁止 [SHALL NOT] 为 agent。
- **影响产物与生效范围**：明确记录该决策波及的章节、数据表格及依赖工件。

---

## 6. 变更维护回路的治理引用

本协议作为全周期治理框架，针对变更事件遵循以下边界：
1. **M8 变更规则引用**：当外部指示或新证据引发既有已审定工件变动时，必须 [SHALL] 遵循 M8 变更回路（`references/change_circuit.md`）协议，由《变更管理与指示处置对照表》（`change-table.md`）承载。本文件仅做治理层引用，严禁 [SHALL NOT] 重复实现 M8 的指示派发与差异校验逻辑。
2. **母本冻结与零漂移联动**：任何进入 `change-table.md` 的变更，在获得人类签署 `gates/change-<id>-approval.md` 放行凭单前，其母本哈希必须 [SHALL] 保持不可变，治理台账中 `T-M8-01` 任务必须 [SHALL] 保持为待触发或处理中状态。
