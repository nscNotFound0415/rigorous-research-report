# brief-elicitation Specification

## Purpose
定义报告启动期的落地澄清访谈决策树算法与简报唯一事实源生成规范。八项核心诉求定位为建议澄清清单，系统通过交互式问答帮助明确研究对象与交付形态，未澄清项逐项登记澄清状态并按协议默认行为执行，不阻断推进；简报内嵌项目宪法与诉求索引，并由 G0 人审放行门禁阻断未经授权的下游规划。

## Requirements

### Requirement: Constitutional Embedding and Sole Source of Truth Declaration
The system SHALL embed the five project constitutional principles and the REQ-ID index into brief.md as the sole source of truth.

#### Scenario: Brief contains explicit constitutional rules and REQ-ID list
- **WHEN** brief.md is generated by the elicitation module
- **THEN** brief.md contains section "3. 项目宪法" listing all 5 inviolable principles verbatim ("事实判锤唯二通路", "定性裁决权归人类", "无隐藏状态", "非同族对抗复核且审者只读", "严禁跨口径相减")
- **AND** python3 scripts/gate_guard.py --verify-brief brief.md returns exit code 0
- **AND** section "2.9 诉求与实体索引" contains at least one machine-readable REQ-ID entry
- **AND** the field brief_content_sha256 matches the SHA-256 hash calculated with that field blank

#### Scenario: Brief with placeholders or invalid pending terms is rejected
- **WHEN** python3 scripts/gate_guard.py --verify-brief brief.md is executed on a brief containing template placeholders, pending terms, out-of-bounds enums, or relative paths
- **THEN** the process returns exit code 1
- **AND** stdout JSON contains {"valid":false} with non-empty errors
- **AND** inherited claims in section 2.11 without valid human decision are rejected

#### Scenario: Sole source of truth declaration line is present verbatim
- **WHEN** python3 scripts/gate_guard.py --verify-brief brief.md is executed on the generated brief.md
- **THEN** the process exit code is 0
- **AND** brief.md contains the verbatim declaration line "本文件为本项目唯一事实源，后续大纲、调研与撰写均由此派生；口径冲突时以本文件为准"

#### Scenario: Missing sole source of truth declaration line is rejected
- **WHEN** python3 scripts/gate_guard.py --verify-brief brief.md is executed on a brief.md whose verbatim declaration line has been removed
- **THEN** the process exit code is 1
- **AND** stdout JSON contains {"valid":false} with a non-empty errors array mentioning the missing authoritative declaration

### Requirement: Gate G0 Human Approval Enforcement
The system MUST block all subsequent execution until gates/G0-approval.md is validated with decision APPROVED and a matching artifact hash.

#### Scenario: Unapproved G0 blocks pipeline execution
- **WHEN** python3 scripts/gate_guard.py --gate G0 --check-only is executed while gates/G0-approval.md is missing or marked PENDING
- **THEN** the process exit code is 1
- **AND** stdout JSON contains {"gate":"G0","state":"PENDING","blocked":true}

#### Scenario: Valid G0 approval permits pipeline execution
- **WHEN** gates/G0-approval.md contains valid human signature, decision APPROVED, and artifact_sha256 matching brief.md
- **THEN** python3 scripts/gate_guard.py --gate G0 --verify --artifact brief.md --approval gates/G0-approval.md returns exit code 0
- **AND** stdout JSON contains {"gate":"G0","state":"APPROVED","blocked":false}

### Requirement: Clarification Status Registration and Default Behavior
The system MUST register clarification_status (CLARIFIED, NOT_CLARIFIED, NOT_APPLICABLE) for each of sections 2.1-2.8 and MUST record unclarified_reason for every non-CLARIFIED item; verification MUST NOT reject a brief solely because an item is not clarified.

#### Scenario: Unclarified soft item passes brief verification
- **WHEN** python3 scripts/gate_guard.py --verify-brief brief.md runs on a brief whose section 2.3 is NOT_CLARIFIED with a non-empty unclarified_reason
- **THEN** the process exits with code 0
- **AND** stdout JSON contains {"valid":true} with an empty errors array

#### Scenario: Unclarified item without reason is rejected
- **WHEN** a section is registered NOT_CLARIFIED or NOT_APPLICABLE without a non-empty unclarified_reason
- **THEN** the process exits with code 1
- **AND** stdout JSON contains {"valid":false} with an error mentioning unclarified_reason

#### Scenario: Invalid clarification status is rejected
- **WHEN** a section declares a clarification_status outside CLARIFIED, NOT_CLARIFIED, NOT_APPLICABLE
- **THEN** the process exits with code 1
- **AND** stdout JSON lists the allowed status values in the error text

#### Scenario: Pending-term scan is limited to clarified items
- **WHEN** a NOT_CLARIFIED item contains the marker 未澄清 in its content and a CLARIFIED item contains the pending term 待定
- **THEN** the NOT_CLARIFIED marker produces no error while the CLARIFIED pending term causes exit code 1

#### Scenario: Default behavior applied for unclarified items
- **WHEN** section 2.7 is NOT_CLARIFIED without online documents and section 2.8 is NOT_CLARIFIED
- **THEN** source_of_truth is LOCAL_AUTHORITATIVE and interaction_mode is synchronous_frontier
- **AND** target_local_dir remains an absolute path in every case

### Requirement: Mandatory Eight Clarifications Elicitation
The system SHALL elicit the eight recommended clarification items through the grill-me decision tree and MUST register a valid clarification_status for each of sections 2.1-2.8 in brief.md before any downstream phase begins; an unclarified item MUST NOT block progression.

#### Scenario: Unclarified dimensions are registered with defaults and do not block progression
- **WHEN** the user initiates elicitation with fewer than eight dimensions clarified
- **THEN** the frontier question queue contains the unclarified dimensions with recommended choices
- **AND** each unanswered dimension is registered as NOT_CLARIFIED with a non-empty unclarified_reason and executed with its protocol default behavior
- **AND** the system creates 0 files in downstream phases until brief.md is approved

#### Scenario: Frontier exhausted and draft brief generated
- **WHEN** the frontier question queue reaches 0 because required questions are answered and all unanswered items are registered with defaults
- **THEN** the system generates brief.md containing all 11 defined sections, with sections 2.1-2.8 each carrying a valid clarification_status
- **AND** the field status is set to DRAFT
